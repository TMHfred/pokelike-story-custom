# 自動化測試與驗收案例（第一版）

> 此文件定義**測什麼**，未聲稱已有測試執行結果。所有數字須按本專案自有戰鬥規格校準，不直接冒稱官方實作。

## A. 戰鬥核心
- B01：相同種子、相同初始隊伍／道具 → 回放結果、回合日誌完全一致。
- B02：屬性一般／剋制／抵抗／免疫四種情境，驗證最終倍率與免疫無傷。
- B03：物理／特殊攻擊使用正確的攻防能力、能力階級與取整順序。
- B04：先手判定、同速時的亂數與優先序有固定契約。
- B05：暴擊和亂數浮動在確定的種子下可重現。
- B06：異常狀態（中毒、灼傷、凍結、睡眠等）的施加、回合起迄與解除。
- B07：連續攻擊／追加攻擊不可無限遞迴；反傷與吸血以明定順序結算。
- B08：角色倒下後不再出手；隊伍全滅正確結束本局。
- B09：裝備有無、禁止組合、同種類疊加限制及百分比上限。
- B10：單次戰鬥可同時觸發特性與裝備，但記錄完整可追蹤結算事件。

## B. 地圖與事件
- M01：生成後每個**可選**節點都與目前節點有合法連線。
- M02：給定種子和版本，地圖拓撲及事件結果可重現。
- M03：道館／重要首領出現的位置與解鎖條件不因難度遺失。
- M04：回血／交易／拾取／捕捉的事件只結算一次。
- M05：六人滿隊伍時加入新人可選替換或取消，不會遺失存檔資料。
- M06：沒有有效路線時應有保底路徑或受控錯誤，不允許無法繼續的死局。

## C. 難度規格
- D01：基準／簡單／休閒／自訂使用同一隊伍和亂數種子對比，差異可解釋。
- D02：調整敵人 HP 不改變物種資料表及敵方正式等級顯示。
- D03：傷害倍率不得意外影響我方反傷、固定傷害、百分比傷害；例外需明訂。
- D04：經驗增益與「直接升級 N 級」的事件分開計算。
- D05：戰後恢復不得復活不應復活的單位，須遵守模式規則。
- D06：一局開始後存檔記錄難度快照；載入時不得被全域預設覆蓋。
- D07：切換難度不應改變道館順序、進化資料、地圖節點合法性。

## D. 存檔與裝置
- S01：開局 → 選路 → 戰鬥 → 關閉 → 繼續，資料一致且不重複獎勵。
- S02：備份匯出／匯入，同版本與跨版本轉換有驗證及可回退措施。
- S03：錯誤、缺欄位、超大檔、未知 schemaVersion 要拒絕或安全遷移。
- S04：本機儲存使用獨立 key，不覆蓋官方網站與其他專案。
- S05：iPhone Safari 直向路線點擊、拖曳替代操作、對話框、文字溢出皆可用。
- S06：快速重複點擊不能導致雙倍道具或同一事件重複發放。

## 驗收紀錄欄位模板
測試 ID｜版本／commit｜平台｜固定種子｜前置隊伍與裝備｜預期結果｜實際結果｜是否通過｜錯誤證據

## 第一個可玩里程碑最小通過集
B01–B04、B08、M01–M06、D01–D02、D04–D06、S01、S04、S05。其他項目隨系統擴充增加，但全劇情版發布前均須驗證。
